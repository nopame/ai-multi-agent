## Brand Strategist

**R1 — จุดยืนเปิด**
- Headline ("ครบทุกชั้น") กับ Tagline ("multi-agent ตรวจย้อนได้") แข่งกันเป็นสองจุดขาย · จุดต่างจริงคือ full-stack + ใช้ AI อย่างมีระบบ + มีหลักฐานใน repo
- Audience: หน้าแรกพูดกับ recruiter / hiring manager กลุ่มเดียว · กลุ่มรองไป About / footer / Later · "มือใหม่" ดึงโทนไปทางสอน ขัดภาพ senior
- **B1** รวม headline เป็นเสียงเดียว · tagline ทำหน้าที่เป็นหลักฐาน ไม่ใช่จุดขายข้อสอง
- **B2** คำหลัก "ครบทุกชั้น · ตรวจสอบได้ · มีระบบ" ต้องมีหลักฐานกำกับทุกครั้ง ไม่มีหลักฐาน = ไม่ใช้
- **B3** Bio เปิดด้วยคุณค่า ไม่ใช่ "สวัสดีครับ" · CTA ชี้ action เดียว
- Tone "สีสนุก ถ้อยคำนิ่ง" ถูกแล้ว ไม่ต้องเปิดถก

**R2 — ตอบโต้**
- รับ U2, U3 · รับ R1 บางส่วน (เอา "5 ปี" ออกจาก headline/tagline) · รับ R8 (พูดผลลัพธ์ ไม่ใช่ขั้นตอน)
- **แย้ง R2:** ไม่ต้องเลือกระหว่าง "ฝีมือโค้ด" กับ "คุม agent" — การคุม agent ให้ส่งครบทุกชั้น *คือ* จุดต่าง แต่ต้องบอกตรง ๆ ว่าใครทำอะไร
- **แย้ง R3 บางส่วน:** นามแฝงเป็น handle ของแบรนด์ได้ ที่ขาดคือช่องทางตอบกลับ ไม่ใช่ชื่อจริง
- แย้ง U4: ตัด "แลกเปลี่ยนความรู้" ออกจาก dropdown
- **B4** GitHub = ตัวตนหลักของแบรนด์ · ตัดช่องทางที่ว่าง (LinkedIn "—")

**R3 — ประเด็นขัดแย้ง C1–C4**
- C1 **ถอย**: ตัด "ครบทุกชั้น" ออก เสนอ "Full-stack developer ที่ออกแบบและคุมทีม AI agent ให้ส่งงานจาก UI ถึง deploy" — แต่ไม่ถอยเรื่องคง "คุม agent" ใน headline
- C2 ลิงก์ GitHub + "ตรวจสอบได้ใน repo" ขึ้นได้เมื่อ audit ผ่าน (ไม่มีชื่อจริง / ไม่มีความลับใน history / CI เขียว)
- C3 ยอมครึ่ง (dropdown optional) — ถ้าทีมเห็นเรื่อง bot สำคัญกว่า ยอมตัดทั้งหมด
- C4 เห็นด้วย UX: success ไม่สัญญาว่าจะตอบกลับ

**R4 — headline + Must**
- กลับไปใช้ "…ที่วางระบบให้ทีม AI agent ส่งงานครบทุกชั้น" เพราะ UX + Devil ยอมรับรูปนี้แล้ว · tagline = ประโยคบทบาท "ผมเขียน spec และ review ส่วน agent แยกกันทำ frontend / backend — ตั้งแต่ UI ถึง deploy"
- Must: Home · About · Deploy 200 · **Audit repo + โปรไฟล์ GitHub** (ใหม่) · Contact = มีเงื่อนไข · เคยยอม ship แบบไม่มีช่องติดต่อ

**R5 — ปิด**
- X1 ยอมตาม UX: H1 "Full-stack developer" + บรรทัดรองที่มี "ครบทุกชั้น" พร้อมคำขยาย
- X2 **ถอนจุดยืน** เห็นด้วย Devil: วัน ship ต้องมีช่องติดต่อใช้ได้จริง ≥ 1
- X3 รวม Interests เข้า About (เสียงข้างน้อย — ดู D12)

## UX Critic

**R1 — จุดยืนเปิด**
- Interests 4 bullet สั้นเกินสำหรับหน้าเต็ม ซ้ำกับ About · Contact: linkedin "—" ถ้า render ตรง ๆ ดูพัง · ยังไม่มี spec ฟอร์ม / success / error / 501
- จุดสับสน: headline vs tagline · เป้าหมาย "ดู repo" แต่ IA ไม่มีทางไป · 4 audience แต่ CTA เดียว · คำเคลมไม่มีลิงก์หลักฐานใกล้ ๆ
- **U1** Interests = "หัวข้อ — ประโยคเดียว" · **U2** ซ่อนช่องทางที่ว่าง · **U3** ปุ่มส้มเดียว "ติดต่อผม" + text link GitHub รอง · **U4** spec ฟอร์ม + microcopy · **U5** ลำดับ About · **U6** มือถือ: ปุ่มติดต่อ above the fold

**R2 — ตอบโต้**
- รับ B1–B3 · R3 = จุดเจ็บที่สุดของ UX · R5: "จะตอบกลับทางอีเมล" = คำสัญญาที่อาจเป็นเท็จ
- **แย้ง Brand:** กลุ่มรองอยู่ในฟอร์ม Contact ได้ ไม่แย่งพื้นที่ Home
- **แย้ง Devil (ธีม → Nice):** ชื่อสีไม่ขวาง ship ได้ แต่ contrast / อ่านง่าย / ปุ่มติดต่อเด่น ต้องเป็น Must
- R4: กัน spam ห้ามทำฟอร์มยาว — ไม่ใช้ CAPTCHA · ใช้ honeypot + rate limit ฝั่ง server
- **U7** ตัวนับ 0/1000 · **U8** ประโยค retention ใต้ฟอร์ม · **U9** error ทุกกรณีบอกทางเลือกถัดไป ไม่มีรายละเอียดเทคนิค

**R3 — ประเด็นขัดแย้ง C1–C4**
- C1 เก็บ "ครบทุกชั้น" ได้เมื่อมีคำขยายบทบาท
- C2 ห้ามลิงก์ไปที่ที่ยังไม่พร้อม (404 / private แย่กว่าไม่มีลิงก์) · ชี้ README ของเว็บ ไม่ใช่ `labs/`
- C3 **ยอม** ตัด dropdown ทั้งหมด · placeholder "เล่าสั้น ๆ ว่าอยากคุยเรื่องอะไรครับ"
- C4 ช่องทางสำรองไม่ผูกฟอร์ม (โปรไฟล์ GitHub) · 501 → ซ่อนฟอร์ม

**R4 — IA + Must**
- Headline ของ Brand ยาว ~70 ตัวอักษร ตัด 3–4 บรรทัดบนจอ 360px → แยก H1 / บรรทัดรอง
- IA: Home (H1 + ปุ่มส้ม above the fold) · About (U5) · Interests (เสนอรวมเข้า About) · Contact (3 ช่อง + U7/U8 + ช่องสำรอง)
- Contact 2 สถานะ: **A** (default / 501) ซ่อนฟอร์ม แสดงช่องสำรอง · **B** เปิดฟอร์มเมื่อ R5 ผ่าน

**R5 — ปิด**
- X1 ใช้ถ้อยคำ Brand ครบใน `<h1>` เดียว แสดง 2 ระดับด้วยขนาดตัวอักษร
- X2 เข้าข้าง Devil — ทางเบาที่สุดคืออีเมลตอบกลับจริงหนึ่งช่อง
- X3 **ถอยจากรอบ 4:** เก็บหน้า Interests (route + API มีอยู่แล้ว) · About แสดงแค่หัวข้อ + ลิงก์ "ดูรายละเอียด"

## Devil's Advocate

**R1 — ความเสี่ยง**
- **R1** overclaim "5 ปี / หลายสแต็ก" ตรวจจาก repo ไม่ได้
- **R2** "ครบทุกชั้น" แต่ backend เขียนโดย agent — ขายฝีมือหรือขายการคุม agent?
- **R3** นามแฝง vs recruiter: ไม่มีชื่อ / LinkedIn + อีเมล demo · GitHub อาจโยงตัวตนจริงผ่าน commit history
- **R4** ฟอร์ม Contact = ช่อง spam (ไม่มี rate limit / honeypot / เพดานความยาว / นโยบาย PII)
- **R5** ฟอร์มเป็นหลุมดำ — ลง SQLite แต่ไม่มีใครอ่าน
- **R6** Guestbook: XSS / spam SEO แต่ไม่ช่วย recruiter · **R7** Nice 7 ข้อเล่าเรื่องเดิมซ้ำ · **R8** Bio เหมือนงานส่ง
- ตัด / แก้ Must: ธีมสี → Nice · About "ครบทุกชั้น" รอหลักฐาน · ฟอร์มต้องกัน spam · Guestbook → Later

**R2 — โจมตีข้อเสนอ**
- B1 "ตรวจสอบได้ใน repo" จริงเฉพาะเมื่อ repo public + สะอาด · B2 หลักฐานย้อนทำร้ายได้ (CI แดง)
- U3 ลิงก์ GitHub เปิดทางไปตัวตนจริง · U4 dropdown เพิ่มช่อง bot + fallback "ทัก GitHub" วนกลับ R3 · U2 ทำให้ฟอร์มเป็นช่องทางเดียว
- ลดระดับ R6 / R7 / R8 · ยังเป็น blocker R1–R5

**R3 — ประเด็นขัดแย้ง C1–C4**
- C1 ยอมใช้ "ครบทุกชั้น" เฉพาะรูป "วางระบบให้ทีม AI agent ส่งงานครบทุกชั้น" + About ต้องมีประโยค "frontend/backend เขียนโดย agent ภายใต้ spec และ review ของผม"
- C2 เช็กลิสต์ audit 5 ข้อ (ดู D8)
- C3 ตัด dropdown ทิ้ง · C4 ก่อนเปิดฟอร์ม: เจ้าของ / อ่าน ≥ สัปดาห์ละครั้ง / ลบหลัง 90 วัน / อีเมลตอบกลับจริง
- ลดระดับ R1, R4 · blocker ค้าง R3, R5

**R4 — ship gate**
- Headline แทบไม่ overclaim แล้ว · "ถึง deploy" ต้องจริงวัน ship
- แยก gate (a) ก่อน Lab 04 ไม่ขวาง frontend · (b) ก่อน ship
- หน้า Contact = Must · ตัวฟอร์ม ≠ Must · ถ้าไม่มีช่องติดต่อใช้ได้เลย = ห้าม ship

**R5 — ปิด**
- X1 เข้าข้าง UX แต่บรรทัดรองห้ามซ่อนบนมือถือ (ไม่งั้นคำเคลมลอย)
- X2 คงจุดยืน: ไม่มีช่องติดต่อ = ห้าม ship
- X3 คงหน้า Interests — ลบ route เขย่า `GET /api/interests` ซึ่งเป็น ownership ของ backend
- สถานะสุดท้าย: R1 ปิด · R2 ลดระดับ · R3 blocker ก่อน ship · R4 ลดระดับ (rate limit ต้องมี test) · R5 blocker ก่อนเปิดฟอร์ม · R6 ปิด · R7 ลดระดับ · R8 ปิด
