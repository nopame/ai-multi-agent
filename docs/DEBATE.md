## Brand Strategist

### รอบ 1

- **Positioning ชัดราว 70%:** แกน "Full-stack developer + ใช้ AI agent อย่างมีระบบ" แตกต่างและจำได้ แต่ขัดกันเอง 3 จุด
  - Headline ขายเรื่อง "วางระบบให้ทีม AI agent" แต่ Bio เปิดด้วย "กว่า 5 ปี" ซึ่ง repo ยืนยันไม่ได้ และขัดกฎ "ไม่อ้างตัวเลขที่ตรวจสอบไม่ได้" ในไฟล์เดียวกัน
  - "Tagline" จริง ๆ เป็นประโยคบอกบทบาท ไม่ใช่ tagline ที่จำได้ → headline ต้องแบกทั้งตำแหน่งและจุดต่าง จึงยาวเกิน
  - "ครบทุกชั้น" / "ถึง deploy" ยังไม่มีหลักฐาน (ยังไม่มี URL 200)
- **Audience:** หน้าแรกพูดกับ recruiter / hiring manager เท่านั้น · กลุ่มรอง 3 กลุ่มดึงข้อความไปคนละทาง → อยู่ About หรือ Later
- **ข้อเสนอ**
  - **B1** Headline 2 ชั้น: H1 "Full-stack developer" + บรรทัดรองเป็นจุดต่าง
  - **B2** คำหลัก (ครบทุกชั้น / ตรวจสอบได้ / มีระบบ) ต้องชี้หลักฐานได้ ไม่งั้นตัด · ลบ "5 ปี" ทุกที่
  - **B3** Bio ≤ 3 ย่อหน้า: คุณค่า → หลักฐาน → CTA · ตัดย่อหน้า "เรียนรู้เทคใหม่" (ข้อความกลาง ๆ)
  - **B4** ตัด LinkedIn "—" · GitHub เป็นตัวตนหลักของแบรนด์ (หลัง audit)
- **ถาม UX:** H1 + บรรทัดรองอ่านจบบน 360px ไหม · ปุ่มส้มอยู่ก่อนหรือหลังลิงก์ repo · **ถาม Devil:** ถ้า audit / URL 200 ไม่ผ่าน ต้องตัด "ครบทุกชั้น" ทั้งหมดไหม

### รอบ 2

- **ตอบ UX:** ประโยค 5 วินาทีแรก = H1 + บรรทัดรอง ไม่ใช่ "Tagline" → **ไม่ต้องเพิ่ม `## Tagline` เข้า parser** ให้ย้ายเป็นประโยคแรกของ Bio · เห็นด้วย U3 (ปุ่มส้มจอแรก) และ U4 (Audience เป็นโน้ตภายใน)
- **ยอม R1 / R2 / R8** — "ครบทุกชั้น" ให้หมายถึง "ชั้นของเว็บนี้" และเปลี่ยนเป็นช่วงที่จับต้องได้
- **ถ้อยคำที่เสนอ:** H1 "Full-stack developer" · บรรทัดรอง "ที่วางระบบให้ทีม AI agent ส่งงานได้ตั้งแต่ UI ถึงฐานข้อมูล" (เติม "ถึง deploy" ได้เมื่อ URL ตอบ 200) · Role statement "ผมเขียน spec และ review ทุก PR ส่วน agent แยกกันเขียน frontend และ backend"
- **ไม่ยอม:** ถ้า audit ไม่ผ่าน → **แก้ audit** ไม่ใช่ตัดจุดขาย "ตรวจสอบได้" ถาวร (ยอมว่าห้ามลิงก์ก่อนผ่าน) · CTA หลักปุ่มเดียว · demo@example.com ≠ ช่องติดต่อ

## UX Critic

### รอบ 1

- **ข้อมูลพร้อมบางส่วน**
  - Interests: parser อ่านได้ แต่เป็นคำนามล้วน → หน้า Interests ไม่ตอบว่า "ทำอะไรกับมัน"
  - `src/lib/profile.ts` **ไม่อ่าน** `## Contact` / `## Tagline` / `## Tone` → ข้อมูลเหล่านี้ยังไม่ขึ้นเว็บ · `linkedin: —` ถ้าแสดง = ลิงก์เสีย
  - Home render Audience ตรง ๆ → ผู้เยี่ยมเห็นโน้ตภายใน "กลุ่มหลัก: Recruiter…"
- **จุดสับสน:** Home ไม่มีปุ่มติดต่อ/ลิงก์ repo แต่มีการ์ด 4 ใบน้ำหนักเท่ากัน (รวม Guestbook) · สรรพนาม "ฉัน" ปน "ผม" · label ฟอร์มภาษาอังกฤษ · หน้า Contact โชว์ `POST /api/contact` · บนมือถือปุ่มติดต่อหลุดจอแรก · Bio อ้าง "ตรวจย้อนได้" แต่ไม่มีลิงก์
- **ข้อเสนอ**
  - **U1** Interests ข้อละบรรทัด "หัวข้อ — ประโยคเดียว" (parser ตัดทีละบรรทัดอยู่แล้ว)
  - **U2** ไม่แสดงช่องทางที่เป็น "—" · ตัดสินว่า parser จะอ่าน Contact / Tagline หรือไม่
  - **U3** Home: headline → tagline → ปุ่มส้ม "ติดต่อผม" ในจอแรกมือถือ → text link รอง "ดูโค้ดของเว็บนี้"
  - **U4** เอารายการ Audience ออกจากหน้าเว็บ
  - **U5** nav 4 หน้า · ซ่อน Guestbook จนมาตรการกัน spam ครบ
  - **U6** label ไทย "ชื่อ / อีเมล / ข้อความ" · ปุ่ม "ส่งข้อความ" · success "ได้รับข้อความแล้วครับ" · error บอกทางไปต่อ · 501 → ซ่อนฟอร์ม
  - **U7** ตัด `POST /api/contact` ออกจากหน้า · maxlength ฝั่ง HTML (ตอนนี้ 2000) ต้องตรง server
- **ถาม Brand:** Tagline คือประโยค 5 วินาทีแรกไหม · **ถาม Devil:** ตอน 501 โชว์แค่ demo@example.com นับว่าติดต่อได้ไหม

### รอบ 2

- **ตอบ Brand:** H1 บรรทัดเดียว · บรรทัดรอง ~2 บรรทัดที่ 360px รับได้ ถ้าเกินให้ตัดคำ ไม่ลด font · จุดตัดบรรทัดห้ามตกกลางคำไทย · **ปุ่มส้มอยู่ก่อน** ลิงก์ repo (text link รองใต้ปุ่มในจอเดียวกัน)
- **ถอดฟอร์มจาก Must: ยอมแบบมีเงื่อนไข** — journey อ่าน → เชื่อ → ติดต่อ ต้องมีช่องใช้ได้จริง ≥ 1 ไม่งั้นห้าม ship
- **demo@example.com ไม่นับ** · ชี้ว่า **ขัดกับ Privacy** ใน PROFILE ตรง ๆ → ส่งให้เจ้าของตัดสิน (ไม่ประนีประนอมแทน)
- **Guestbook → Later: ยอม**
- **ปรับ U2:** เปลี่ยนชื่อหัวข้ออย่างเดียวผู้เยี่ยมไม่เห็นอะไร — ต้องให้ parser อ่าน หรือย้ายเนื้อหาไปหัวข้อที่ parser อ่านอยู่แล้ว · **ปรับ U3:** H1 → บรรทัดรอง → ปุ่มส้ม → ลิงก์ "ดูโค้ด" (หลัง audit)
- **IA:** Interests **คงหน้าแยก** (route + API มีแล้ว) · About แสดงหัวข้อ + ลิงก์ · รับโครง Bio ของ Brand แต่ย่อหน้าหลักฐานต้องมีลิงก์กดได้จริง

## Devil's Advocate

### รอบ 1

- **ความเสี่ยง**
  - **R1** "5 ปี" overclaim — repo พิสูจน์ได้แค่งานชิ้นเดียว
  - **R2** "ครบทุกชั้น" ยืนเดี่ยว = อ่านว่าเขียนเองทุกชั้น ขัดกับ Tagline/Bio ที่บอกว่า agent เขียน
  - **R3** นามแฝงโยงกลับตัวตนจริงผ่าน GitHub (author ใน git log, รูป, บริษัท) — ไม่มีขั้นตอน audit
  - **R4** ฟอร์มโดน spam / ถล่ม SQLite จน volume เต็ม — ไม่มี honeypot / rate limit / เพดาน
  - **R5** ฟอร์มหลุมดำ — ใครอ่าน กี่วัน ตอบกลับทางไหน (demo@example.com ตอบไม่ได้) เก็บข้อมูลกี่วัน
  - **R6** Guestbook — เนื้อหาคนแปลกหน้าขึ้นเว็บทันที เสี่ยงเกินประโยชน์
  - **R7** scope บวม — Nice 7 ข้อ หลายข้อผูกกับลิงก์ repo (R3)
  - **R8** Bio เล่าการแบ่งงาน agent เหมือนรายงานส่งการบ้าน
- **คำถามก่อน ship:** หลักฐาน "5 ปี" · "ครบทุกชั้น" หมายถึงเขียนเองหรือกำกับ agent · audit GitHub · เจ้าของ inbox / รอบอ่าน / retention · rate limit มี test ไหม · 501 วัน ship แสดงอะไร · "ถึง deploy" จริงไหม
- **ตัด/ลดจาก Must:** ฟอร์ม "บันทึกลง SQLite ได้จริง" → เงื่อนไข (ship ได้ถ้าซ่อนฟอร์มแต่มีช่องสำรอง) · ตัด "5 ปี" · ชื่อสีไม่ขวาง ship แต่ contrast = Must · Guestbook → Later · แช่แข็ง Nice
- **จุดยืน:** ไม่มีช่องติดต่อใช้ได้ ≥ 1 + audit ไม่ผ่าน = ห้าม ship

### รอบ 2

- **ตอบ Brand:** audit / URL 200 ไม่ผ่าน → ตัด "ครบทุกชั้น" ทั้งหมด ไม่รับหลักฐานทดแทน (screenshot / คำบรรยาย) · ถอยไปใช้บรรทัดรองที่ไม่อ้างเกิน
- **ตอบ UX:** demo@example.com **แย่กว่าไม่มี** (`example.com` เป็นโดเมนสงวน) · ช่องสำรองต้องตอบได้จริงโดยไม่เปิดตัวตน เช่น อีเมล alias ของนามแฝง
- **สถานะ R:** R1 ปิด (เมื่อลบจริง) · R2 ลดระดับ · **R3 blocker** (B4/U3 ทำให้ GitHub สำคัญขึ้น) · R4 ลดระดับ ยังขาด honeypot + rate limit ที่มี test · **R5 blocker ก่อนเปิดฟอร์ม** · R6 ซ่อนอย่างเดียวไม่พอ ต้องย้าย Later ชัด · R7 ลดระดับ · R8 ลดระดับ (guard test ต้องเขียว)
- **ท้าทาย:** ลิงก์ "ดูโค้ด" ห้ามฝัง URL จริงก่อน audit — ต้องเป็น slot เปิด/ปิด · B4 ทำให้ R3 เป็น single point of failure · **ลิงก์ PR** ในประวัติมี revert/อ้าง Lab = ยืนยันว่าเป็นการบ้าน → ใช้ badge CI + URL 200 แทน · success "ได้รับข้อความแล้วครับ" จริงเมื่อ R5 ผ่านเท่านั้น · "ส่งงานได้ทุกชั้น" ในบรรทัดรองคือคำเคลมเดิมที่ย้ายที่
- **Gate:** ก่อน Lab 04 = ล็อกถ้อยคำ + slot ลิงก์ + 501 ห้ามโชว์อีเมล demo + maxlength ตรงกัน · ก่อน ship = audit 5 ข้อ + R5 + rate limit test + URL 200 + guard test + ช่องติดต่อจริง ≥ 1
