# UX Critic — MEMORY (debate ใหม่จาก PROFILE.md ปัจจุบัน · รอบ 1–2 · 2026-09-25)

## บทบาท
มองจากผู้เยี่ยม (end-user) · IA 4 หน้า Home/About/Interests/Contact · microcopy · มือถือ · read-only ต่อ docs/ และ src/

## ข้อเท็จจริงที่เช็กแล้ว (src อ่านอย่างเดียว)
- profile.ts อ่านแค่ Name/Headline/Bio/Audience/Interests: ไม่อ่าน Tagline/Contact/Tone
- ตอนนี้ Home แสดงรายการ Audience ออกหน้าเว็บ · การ์ดใช้ "ฉัน" · มีการ์ด Guestbook
- Contact แสดง `POST /api/contact` · label เป็นภาษาอังกฤษ · textarea maxlength=2000

## จุดยืนหลังรอบ 2 (U1–U7)
- U1: Interests เขียนบรรทัดเดียวต่อข้อ ในรูป "หัวข้อ — ประโยคเดียว"
- U2: ไม่แสดงช่องทางที่ว่าง ("—") · Contact/Role statement จะขึ้นเว็บได้ต้องให้ parser อ่านหัวข้อนั้น หรือย้ายไปอยู่ในหัวข้อที่ parser อ่านอยู่แล้ว
- U3: Home ใช้ H1 สั้น + บรรทัดรองไม่เกิน 2 บรรทัดที่จอ 360px → ปุ่มส้ม "ติดต่อผม" (ต้องเห็นในจอแรก) → ลิงก์ repo เป็น text link รองอยู่ติดปุ่ม (แสดงหลังผ่าน audit)
- U4: เอารายการ Audience ออกจากหน้าเว็บ
- U5: nav มี 4 หน้า · Guestbook ไป Later
- U6: label ฟอร์มเป็นภาษาไทย · success "ได้รับข้อความแล้วครับ" · error ต้องบอกทางไปต่อ · ได้ 501 = ซ่อนฟอร์ม + แสดงช่องสำรอง
- U7: ตัดบรรทัด API path ออก · เพดานความยาวที่หน้าเว็บต้องตรงกับ server

## IA
- Interests เป็นหน้าแยก (มี route + API อยู่แล้ว) แสดงแบบเต็มตาม U1 · About แสดงแค่หัวข้อ + ลิงก์ไปหน้า Interests
- About: Bio ไม่เกิน 3 ย่อหน้า (คุณค่า → หลักฐาน → CTA)

## ยอม / ไม่ยอม
- ยอมถอดฟอร์มออกจาก Must แบบมีเงื่อนไข: ต้องมีช่องทางที่ติดต่อได้จริงอย่างน้อย 1 ช่อง ไม่งั้น journey หลักพัง (ตรงกับ Devil)
- demo@example.com ไม่นับเป็นช่องทางจริง: ขัดกับข้อ Privacy (ใช้อีเมล demo) → ต้องให้ Brand/เจ้าของตัดสิน
- Guestbook → Later: ยอม

## session ถัดไปต้องเช็ก
- ที่ 360px: บรรทัดรองไม่เกิน 2 บรรทัด ตัดคำภาษาไทยไม่กลางคำ · ปุ่มเห็นในจอแรก
- 501 → ฟอร์มถูกซ่อน และช่องสำรองใช้ได้จริง

มติจริงอยู่ใน docs/DECISIONS.md (facilitator เป็นผู้เขียน) — ถ้าขัดกับไฟล์นี้ ให้ยึด DECISIONS
