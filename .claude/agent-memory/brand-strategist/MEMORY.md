## จุดยืนที่ปิดแล้ว (debate 5 รอบ · 2026-09-25)
- B1 Headline แบ่ง 2 ระดับ: H1 "Full-stack developer" + บรรทัดรอง "ที่วางระบบให้ทีม AI agent ส่งงานครบทุกชั้น"
  - ประโยคบทบาท: "ผมเขียน spec และ review ส่วน agent แยกกันทำ frontend / backend — ตั้งแต่ UI ถึง deploy"
- B2 ทุกคำหลัก (ครบทุกชั้น / ตรวจสอบได้ / มีระบบ) ต้องมีหลักฐานกำกับ ถ้าไม่มีหลักฐานก็ไม่ใช้คำนั้น
- B3 Bio ไม่เกิน 3 ย่อหน้า: คุณค่า → ประสบการณ์ (ไม่มีตัวเลขปี) → CTA · ไม่เล่ารายละเอียด workflow แบบการบ้าน
- B4 GitHub คือตัวตนหลักของแบรนด์ (ต้องผ่าน audit ก่อน) · ตัดช่องทางติดต่อที่ว่าง เช่น LinkedIn "—"
- Audience หน้าแรก: recruiter / hiring manager เท่านั้น
- Tone: สีสนุก ถ้อยคำนิ่ง (ไม่เปิดถกใหม่)

## สิ่งที่ยอมถอยและเหตุผล
- ตัด "5 ปี" ออกจาก headline (R1) เพราะตรวจจาก repo ไม่ได้
- "ครบทุกชั้น" ใช้ได้เฉพาะเมื่อมีคำขยายบทบาท "วางระบบให้ทีม AI agent" (R2) ห้ามใช้เดี่ยว ๆ
- แบ่ง headline เป็น H1 + บรรทัดรองตาม UX เพราะบรรทัดเดียวยาวเกินจอมือถือ 360px
- ตัด dropdown ในฟอร์มทั้งหมด (C3) เพราะเป็นช่องให้ bot และดึงกลุ่มรองกลับมา
- success copy คือ "ได้รับข้อความแล้วครับ" ไม่สัญญาว่าจะตอบกลับ (R5)
- ถอนข้อที่ยอม ship แบบไม่มีช่องติดต่อ → เห็นด้วยกับ Devil ว่าต้องมีช่องทางติดต่อที่ใช้ได้จริงอย่างน้อย 1 ช่องจึงจะ ship
- Interests รวมเข้าหน้า About ใน v1 (ในแง่แบรนด์ ความสนใจเป็นส่วนหนึ่งของเรื่องเล่า)

## เช็กในเซสชันถัดไป
- Audit C2 ครบ 5 ข้อหรือยัง (git log ไม่มีความลับ / author เป็นนามแฝง / โปรไฟล์ GitHub ไม่มีชื่อจริง / CI main เขียว / README บอกว่าเป็นผลงาน)
- วลี "ตรวจสอบได้ใน repo" + ลิงก์ GitHub เปิดได้เมื่อ audit ผ่านเท่านั้น
- "ถึง deploy" จริงเมื่อ public URL ตอบ 200 แล้วเท่านั้น ถ้ายังไม่ผ่านให้ตัดออก
- Contact ยังติด R5 (อีเมลตอบกลับยังเป็น demo · ยังไม่มีคนอ่าน/รอบอ่าน/retention)
- อ่าน docs/DECISIONS.md ก่อน ถ้ามี D-id ที่ปิดแล้ว อย่าเปิดถกซ้ำโดยไม่มีเหตุผลใหม่
